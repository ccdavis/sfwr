# Repository Guidelines

## Project Structure & Module Organization
- `main.go` is the CLI entry point; flags control database creation, the web UI, and static builds.
- `models/` holds GORM models and Open Library integration.
- `pages/` generates static HTML; `templates/` contains site templates and `templates/web/` contains CRUD UI templates.
- `web/` provides HTTP handlers for the management UI; `tui/` hosts the interactive CLI; `load/` handles JSON imports.
- Data and assets live in `sfwr_database.db`, `book_database.json`, and `saved_cover_images/`; generated output goes to `output/public/`.

## Build, Test, and Development Commands
- `go build -o sfwr` builds the CLI binary.
- `go run main.go -web=8080` or `./sfwr -web=8080` starts the local web UI.
- `./sfwr -createdb sfwr_database.db` initializes a new SQLite database.
- `./sfwr -build` renders the static site to `output/public/`.
- `./sfwr -getimages` fetches cover images from Open Library.
- `go test ./...` runs unit and integration tests.
- `./deploy.sh` (optional) builds and pushes to `gh-pages` for local deployment.

## Coding Style & Naming Conventions
- Use `gofmt` (tabs, standard Go formatting); keep functions small and focused.
- Follow Go naming: `PascalCase` for exported types/functions, `camelCase` for locals.
- Tests live in `*_test.go`; keep template names aligned with their pages (e.g., `templates/book.html`).

## Testing Guidelines
- Tests use Go’s `testing` package with in-memory SQLite where possible.
- Add tests for new handlers/pages and model logic; keep fixtures local to tests.
- Run focused tests with `go test ./... -run TestName`.

## Commit & Pull Request Guidelines
- Commit messages are short and descriptive; deployment snapshots use the `[DEPLOY]` prefix.
- PRs should include a clear summary, test commands run, and screenshots if templates/UI change.
- If adding large images or databases, note whether Git LFS is required.

## Security & Configuration Notes
- The admin UI binds to `127.0.0.1` by default. Publishing it requires a password (`SFWR_ADMIN_PASSWORD_HASH`, generated by `./sfwr -hash-password`) and a TLS-terminating reverse proxy with `-behind-proxy`; the server refuses to start otherwise.
- Deploy, rollback, and local build run commands on the server and are restricted to browsers on the machine itself, even when the rest of the UI is published.
- Every non-GET request needs a CSRF token; new forms must include the hidden `{{.CSRFFieldName}}` field. See the Admin Web UI section of `CLAUDE.md`.
- See `DEPLOYMENT.md` and `GETTING_STARTED.md` for hosting and GitHub Pages setup details.
